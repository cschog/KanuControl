# KanuControl V1.7.0 -- Was ist neu?

## Dynamische Datenvollständigkeit und kontextabhängige Validierung

KanuControl V1.7 führt ein neues Konzept für die Datenvollständigkeit
ein: Ein Datensatz muss nicht mehr von Anfang an vollständig sein.
Entscheidend ist, ob die vorhandenen Daten für die **aktuelle
Verwendung** ausreichen.

Damit können Personen, Vereine und Veranstaltungen zunächst mit den
notwendigen Grunddaten angelegt und später gezielt ergänzt werden.

> **Ein Datensatz muss nicht vollständig sein. Er muss für seine
> aktuelle Verwendung ausreichend vollständig sein.**

------------------------------------------------------------------------

## 1. Dynamische Datenvollständigkeit

Bisher war es schwierig, zwischen wirklich erforderlichen Daten und
lediglich hilfreichen Angaben zu unterscheiden.

Mit V1.7 wird deshalb zwischen drei Situationen unterschieden:

-   🔴 **Rot -- erforderlich:** Ein für die aktuelle Verwendung
    benötigtes Datum fehlt.
-   🟡 **Gelb -- empfohlen:** Das Datum ist für spätere Vorgänge oder
    Dokumente sinnvoll, blockiert den aktuellen Vorgang aber nicht.
-   **Kein Status:** Es besteht aktuell kein Handlungsbedarf.

Die Bewertung erfolgt **dynamisch anhand der tatsächlichen Verwendung**
eines Datensatzes.

Ein Datum kann deshalb zunächst nicht erforderlich sein und später --
beispielsweise durch die Verwendung einer Person als
Veranstaltungsleiter -- erforderlich werden.

------------------------------------------------------------------------

## 2. Speichervalidierung und Vorgangsvalidierung werden getrennt

Eine wichtige Neuerung von V1.7 ist die klare Trennung zwischen:

### Speichervalidierung

Hier wird geprüft:

> **Darf dieser Datensatz gespeichert werden?**

Die bisherigen technischen und fachlichen Voraussetzungen für das
Speichern bleiben bestehen.

### Kontextabhängige Datenprüfung

Zusätzlich wird geprüft:

> **Welche Daten werden für die aktuelle Verwendung benötigt?**

Diese Anforderungen werden nicht pauschal als Pflichtfelder für jeden
Datensatz definiert.

### Vorgangsvalidierung

Bei einem konkreten Vorgang -- insbesondere bei der Erstellung von
Dokumenten und PDFs -- wird erneut geprüft, ob alle dafür tatsächlich
erforderlichen Daten vorhanden sind.

Fehlen erforderliche Daten, kann der Vorgang bzw. die Dokumenterstellung
blockiert werden.

Empfohlene Daten bleiben dagegen optional.

------------------------------------------------------------------------

## 3. Datenstatus direkt in den Listen

Die neuen Datenstatus werden direkt in den relevanten Listen sichtbar.

Dies betrifft unter anderem:

-   Personen
-   Teilnehmer
-   Vereine
-   Veranstaltungen

Dabei werden nur Datensätze mit tatsächlichem Handlungsbedarf
gekennzeichnet.

Es gibt bewusst **kein grünes Statussymbol**. Vollständige Datensätze
benötigen keine zusätzliche Kennzeichnung.

Dadurch soll schnell erkennbar sein, wo tatsächlich noch etwas ergänzt
werden sollte oder muss.

------------------------------------------------------------------------

## 4. Dynamische Hinweise in den Detailformularen

Auch in den Detailformularen werden fehlende Angaben abhängig von ihrer
aktuellen Bedeutung gekennzeichnet.

Dabei wird nicht nur angezeigt, **dass** ein Feld fehlt, sondern auch,
**warum** es relevant ist.

Beispielsweise kann ein fehlendes Geburtsdatum bei einer normalen Person
zunächst unproblematisch sein. Wird diese Person später als
Veranstaltungsleiter eingesetzt, kann das Geburtsdatum zu einem
erforderlichen Feld werden.

Die Kennzeichnung erfolgt direkt am jeweiligen Feld.

------------------------------------------------------------------------

## 5. Verständliche Tooltips

Die Statusanzeigen werden durch erklärende Tooltips ergänzt.

So kann beispielsweise erklärt werden:

-   warum ein Geburtsdatum für einen Veranstaltungsleiter erforderlich
    ist,
-   warum eine Bankverbindung empfohlen wird,
-   ob fehlende Daten einen Vorgang tatsächlich blockieren.

Damit wird aus einer technischen Fehlermeldung eine konkrete
Handlungsinformation.

------------------------------------------------------------------------

## 6. Erster Anwendungsfall: Veranstaltungsleiter

Ein wichtiger Schwerpunkt von V1.7 ist die Verwendung einer Person als
Veranstaltungsleiter.

Eine Person kann zunächst mit ihren Grunddaten angelegt werden.

Erst wenn sie als Veranstaltungsleiter eingesetzt wird, werden
zusätzliche Angaben relevant, insbesondere:

-   Geburtsdatum
-   Straße
-   Postleitzahl
-   Ort
-   E-Mail-Adresse
-   Telefonnummer

Fehlen diese Angaben, werden sie entsprechend als erforderlich
gekennzeichnet.

Die Person kann trotzdem weiterhin gespeichert und bearbeitet werden.
Die Vollständigkeit wird dort eingefordert, wo sie für die konkrete
Verwendung tatsächlich benötigt wird.

------------------------------------------------------------------------

## 7. Veranstaltender Verein

Auch bei Vereinen wird die Datenvollständigkeit an die Verwendung
gekoppelt.

Ein neu angelegter Verein kann zunächst als grundlegende
Zuordnungseinheit verwendet werden.

Angaben wie

-   Kontoinhaber
-   Bankname
-   IBAN
-   BIC

müssen nicht bereits bei der ersten Anlage vollständig vorhanden sein.

Wird der Verein später als Veranstalter verwendet, können bestimmte
Angaben für den weiteren Prozess erforderlich werden.

Die Bankdaten bleiben grundsätzlich eine sinnvolle Ergänzung und werden
-- sofern sie für spätere Dokumente relevant sind -- als empfohlen
gekennzeichnet.

------------------------------------------------------------------------

## 8. Veranstaltungen und Simulation

Auch Veranstaltungen werden schrittweise vervollständigt.

Der typische Ablauf in V1.7 orientiert sich dabei an der tatsächlichen
Verwendung:

**Verein → Person → Veranstaltung → Veranstalter → Veranstaltungsleiter
→ Datenstatus → Simulation → Antrag/Planung**

Dabei werden Anforderungen erst dann aktiviert, wenn sie für den
jeweiligen Schritt relevant werden.

Auch die Simulation berücksichtigt die konkrete Veranstaltung.

Beispielsweise ist eine Unterkunft bei einer Tagesveranstaltung nicht
erforderlich. Bei einer Veranstaltung mit Übernachtung kann diese
Information dagegen relevant werden.

------------------------------------------------------------------------

## 9. Dokumente und PDF-Erstellung

Vor der Erstellung von Dokumenten werden die benötigten Daten gezielt
geprüft.

Dabei gilt:

-   🔴 Fehlende erforderliche Daten können die Dokumenterstellung
    blockieren.
-   🟡 Fehlende empfohlene Daten blockieren die Dokumenterstellung
    nicht.
-   Vorhandene Daten können automatisch in Dokumente übernommen werden.
-   Fehlende optionale Angaben können gegebenenfalls manuell im Dokument
    ergänzt werden.

Damit wird die Dokumentprüfung stärker an den tatsächlichen Inhalt und
Zweck des jeweiligen Dokuments angepasst.

------------------------------------------------------------------------

## 10. Erweiterte Personenverwaltung

Die Personenverwaltung wurde erweitert.

Unter anderem stehen nun Funktionen zur gezielteren Auswahl von Personen
und zum CSV-Export zur Verfügung.

Damit lassen sich Personenbestände einfacher auswählen und für weitere
Verarbeitungsschritte exportieren.

------------------------------------------------------------------------

## 11. Verbesserungen bei Daten- und Dokumentprüfungen

Die Validierung wurde über mehrere Bereiche hinweg erweitert.

Dabei werden unter anderem Personen-, Vereins- und Veranstaltungsdaten
sowie die Dokumenterstellung berücksichtigt.

Die Prüfungen liefern strukturierte Hinweise mit einer Unterscheidung
zwischen:

-   erforderlichen Angaben
-   empfohlenen Angaben

Dadurch können fehlende Daten gezielter dort angezeigt werden, wo sie
tatsächlich benötigt werden.

------------------------------------------------------------------------

## 12. Verbesserte Testumgebung

Mit V1.7 wurde die Testumgebung von KanuControl deutlich stärker von der
Produktivumgebung getrennt.

Die Testumgebung verfügt über eigene Komponenten für:

-   Authentifizierung
-   Datenbank
-   KanuControl-Server
-   virtuelle Maschine

Dadurch können Änderungen und neue Funktionen unabhängig von der
Produktivumgebung getestet werden.

------------------------------------------------------------------------

## 13. Automatischer Logout bei Inaktivität

Für die Sicherheit wurde ein automatischer Logout bei längerer
Inaktivität ergänzt.

Nach **30 Minuten ohne Benutzeraktivität** wird die Sitzung automatisch
beendet.

Damit wird verhindert, dass eine offene KanuControl-Sitzung über längere
Zeit unbeaufsichtigt bestehen bleibt.

------------------------------------------------------------------------

## 14. Verbesserungen für mobile Geräte

Die Darstellung und Bedienung wurde insbesondere für kleinere
Bildschirme weiter verbessert.

Unter anderem werden Fehler und Warnungen nun auch im Teilnehmerbereich
auf mobilen Geräten sichtbar angezeigt.

Auch die Anordnung der unteren Aktionsbereiche wurde für
unterschiedliche Bildschirmgrößen optimiert.

------------------------------------------------------------------------

# Was bedeutet V1.7 für den normalen Arbeitsablauf?

Mit V1.7 müssen nicht mehr alle denkbaren Informationen bereits bei der
Anlage eines Datensatzes vorhanden sein.

Stattdessen kann schrittweise gearbeitet werden:

1.  **Grunddaten anlegen**
2.  **Datensatz verwenden**
3.  **Fehlende relevante Daten erkennen**
4.  **Erforderliche Daten ergänzen**
5.  **Vorgang oder Dokument erstellen**

KanuControl zeigt dabei frühzeitig, welche Angaben für die aktuelle
Verwendung noch fehlen oder später sinnvoll sein können.

------------------------------------------------------------------------

# Wichtig für bestehende Anwender

Bei der Arbeit mit V1.7 sollte insbesondere auf die neuen Statusanzeigen
geachtet werden.

### 🔴 Rot

Die Angabe wird für die aktuelle Verwendung benötigt und sollte ergänzt
werden.

Wenn die Angabe für einen konkreten Vorgang zwingend erforderlich ist,
kann dieser Vorgang ohne die Information nicht abgeschlossen werden.

### 🟡 Gelb

Die Angabe ist für spätere Vorgänge oder Dokumente sinnvoll, blockiert
den aktuellen Vorgang aber nicht.

Es besteht daher kein unmittelbarer Zwang zur Ergänzung.

### Kein Status

Aktuell besteht kein Handlungsbedarf.

------------------------------------------------------------------------

# Das neue Grundprinzip von KanuControl

V1.7 verändert damit nicht nur einzelne Formulare oder Prüfungen,
sondern das grundsätzliche Verständnis von Datenvollständigkeit:

> **Nicht jeder Datensatz muss jederzeit vollständig sein. Entscheidend
> ist, ob er für seine aktuelle Verwendung ausreichend vollständig
> ist.**

Dadurch können Daten schrittweise erfasst werden, ohne Benutzer bereits
bei der Anlage mit allen möglichen späteren Anforderungen zu belasten.

Gleichzeitig macht KanuControl sichtbar, welche Informationen für den
nächsten konkreten Arbeitsschritt benötigt werden.

------------------------------------------------------------------------

# Kurz gesagt

**KanuControl V1.7 macht Datenvollständigkeit dynamisch.**

Statt pauschal alle Felder als Pflichtfelder zu behandeln,
berücksichtigt KanuControl den tatsächlichen Zusammenhang, in dem Daten
verwendet werden.

Das Ergebnis:

-   weniger unnötige Pflichtangaben bei der Datenerfassung,
-   frühzeitige Hinweise auf tatsächlich benötigte Daten,
-   klare Unterscheidung zwischen erforderlich und empfohlen,
-   verständliche Hinweise direkt in Listen und Formularen,
-   gezielte Prüfung vor Dokument- und PDF-Erstellung,
-   schrittweise Vervollständigung der Daten,
-   bessere Unterstützung des gesamten Arbeitsablaufs.

**V1.7 steht damit für eine schrittweise und verwendungsabhängige
Datenvollständigkeit statt einer pauschalen Vollständigkeitsprüfung.**
